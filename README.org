[[https://github.com/NousResearch/hermes-agent][Hermes]], Nous Research's agent, as one of the
editor's agents of [[https://github.com/LispMachineLab/lispm-agent][LispM Agent]], beside Claude Code
and Codex.  It needs lispm-agent alone and works in any Emacs 30.1 or later;
[[https://github.com/LispMachineLab/lispm-desktop][LispM Desktop]]'s App Store installs it from its
Extensions.  In code, the prefix is ~lispm-hermes-~.

* What it does

While ~hermes~ is on ~PATH~, Hermes takes part as Claude Code and Codex do:

- =h= in ~lispm-agents-map~ (=C-c a h= in LispM Desktop, where its agents sidebar and λ menu
  offer it too) starts Hermes, in a terminal, at the current project's root.
- Its sessions join the others in ~lispm-agents-sessions~ (=C-c a s=), grouped by project, and
  resume where they ran.  They are read from Hermes's own store, =~/.hermes/state.db=, again only
  when it changed; renaming, deleting and opening a transcript go through the ~hermes~ command,
  as the store is Hermes's.
- ~lispm-agents-send-region~ (=C-c a r=) puts the region, with where it is, into a running Hermes's input.
- It sees what only Emacs knows: the selection, the files open and unsaved, Flymake's
  diagnostics, over MCP.  Each terminal gets a server of its own, reached through this package's
  bridge, =bin/emacs-mcp=, which Hermes's config names once as its server ~emacs~:
  =M-x lispm-hermes-setup= has Hermes add it (answer yes when it asks to save a server that offers
  no tools outside a terminal).

Without ~hermes~ on ~PATH~, Hermes shows nowhere, and LispM Desktop's App Store greys it out with
the command installing it.

* Installation

From LispM Desktop's App Store: Extensions, Hermes, Get.  Removing it there takes Hermes away
from the editor at once; its sessions stay in Hermes's store.

By hand, from a checkout, with lispm-agent's =lisp/= on the load path:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/src/lispm-hermes")
(require 'lispm-hermes)
(keymap-global-set "C-c a" lispm-agents-map)
#+end_src
